# Five-minute demonstration plan

Use a known cube state and keep a dated backup recording of the same scenario.

| Time | Demonstration | Evidence/rubric purpose |
|---|---|---|
| 0:00-0:30 | State the problem, Raspberry Pi components, and controlled requirement change | Embedded context and formal process |
| 0:30-2:00 | Capture the four guided angled views; show either safe reconstruction or the direct yellow fallback | Camera integration, usability, and reliability |
| 2:00-2:50 | Show validation, calculated solution, and initial move guidance using the keyboard | End-to-end integration |
| 2:50-3:30 | Show the local SQLite terminal record | Deterministic local evidence and offline availability |
| 3:30-4:15 | Use a slow/offline server while the interface remains responsive, then restore it and show one upload | Meaningful multithreading and LAMP integration |
| 4:15-4:45 | Show the dashboard plus accuracy and timing summaries | Requirements-based measured results |
| 4:45-5:00 | Show the architecture/traceability view and identify team contributions | Coherence, communication, and sustained teamwork |

## Recovery plan

- Keep the backup video, known cube, database query, and dashboard page ready.
- If live networking fails, show the pending local row and the previously retained
  reconnect evidence rather than claiming a successful live upload.
- If camera lighting changes, use the documented controlled-lighting setup and explain
  the limitation; do not substitute unmeasured claims.
